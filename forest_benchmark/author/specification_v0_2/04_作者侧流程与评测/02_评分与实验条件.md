# 评分与实验条件

## 每任务的报告结构

| 项 | L1 | L2 |
|---|---|---|
| 核心数值 | 本级 10 例 | 新增算法 10 例 |
| 前级数值回归 | 不适用 | 同一前级 10 例，单独统计 |
| GPU/渲染一致性 | 必须 | A、B 和依赖均必须 |
| 因果联动 | 不适用 | 每题 5 组，不用“同时出现”替代 |
| 视觉 | 本题锚定 rubric | A、B、组合与时序 |
| 文件/资源保护 | 必须 | 包含前级保护 |
| 运行预算 | 独立记录 | 含状态更新与合成 |

数值组只有全部必需输出在公开容差内才通过，记录最坏/均值/分位误差以诊断。正式任务通过的建议门槛为：全部数值组和硬性保护/联动通过，再满足预先冻结的视觉阈值；仍展示部分成绩。不要用 VLM 高分抵消错误数学、假依赖或越权。视觉阈值未标定前只给分、不判正式通过。

VLM 每项 0–4：0 未出现/目标相反；1 严重缺陷；2 部分达成但有明显缺陷；3 主目标成立、局部轻微缺陷；4 在给定观察条件下达成且无可见缺陷。按各题视觉条目补充例图/判分说明，并在模型测试前固定。每分须关联帧/时间。审阅隐藏模型标识，不向 VLM 展示实现者名称或未证实的代码自评。

## 继承条件

主实验 `self_predecessor`：继承同一被测模型的前级 solution、同一链运行记录；冻结并记录哈希。前级部分失败仍可进入 L2，但必须记录前级起始成绩和所做修复。

诊断实验 `gold_predecessor`：提供统一合格的前级解，只考新增算法与联动。此条件明确获得前级代码，不属于泄露本级解；不得把两条件合并统计或作为同样的信息预算。

修复前级的耗时/交互计入 L2 预算。为控制上下文效应，冻结继承方式：代码+简要交接信息，或完整对话历史；不同方式单列，不能按模型临时选择。

## Agent 条件

默认 `direct`，不要求固定 plan 或自建验证场景。可选 `plan` 和 `plan_verify` 作为独立实验标签；与此前 Three.js 提示的思想对应，但不宣称等同仓库 S1/P3/P1/P2 的具体实现。

只有公开调试工具可给模型调用，最终正式隐藏测试不作为无限次交互奖励。冻结每轮工具、失败反馈粒度和调用预算。可以公开失败类别及统计，禁止把隐藏 expected/坐标/种子原样回传。

## 预算与性能

冻结 wall_time_s、tokens 或等价推理预算、tool_calls、public_test_calls、最大内存/分配、采样/粒子上限、GPU 帧时间测量方式、热身/采样窗口、帧率与模拟 dt。不同模型使用相同已声明预算条件，不默认为每题 1 轮。

必要的固定 dt 可用合法子步，但正式数值契约规定离散一步的题不可用另一数值方案冒充相同步骤。效果帧耗时不含离线 CPU 参考、诊断截图编码和强制 GPU 回读；这些额外耗时单独报告。

## v0.2：L3报告与C分支

L3报告20项前级数值、5组前级联动、10组本级集成覆盖、独立保护、视觉和预算。self/gold改为继承完整L2，修复计入L3预算。C_R/C_S共享起始L2哈希，独立运行且不交换中间成果。任务级可展示6个分数，链级C先内部汇总后与A/B/D/E宏平均，避免重复加权。详见[L3发布与评分](06_L3发布门禁与评分.md)。
