# 发布前验收

## Gate 0：规范与环境

精确锁定 Godot、渲染方法、平台/驱动和数据格式。检查公共契约之间无歧义。把本次新增约定与已确认方案的差异记录在 changelog。确认环境 lock 中没有必填 null。先跑一个已知数值 GPU 回读和一个层捕获小样，不把 headless 启动成功当作 GPU 可用。

## Gate 1：独立参考

CPU float64 参考通过解析/退化测试。GPU 参考与 CPU 一致，最终效果与探针核心一致。实现不是在输出路径上缓存标准答案。内置算法允许/禁止边界已公开。

## Gate 2：逐题正负对照

每题的 10 个数值组全部有输入、独立期望、容差与失败说明；L2 的 5 个联动组有干预、保护变量、观测量和判定。每种文档指定的错误实现至少有一个检测能抓住；至少一份合法替代/不同采样实现不得因无关实现细节被误拒。

如果错误对照通过，优先修检测；如果合法实现失败，检查输入契约、数值误差与阈值，而不是强迫完全复制作者代码。

## Gate 3：空白场景与继承

所有 starter 只含中性输入和桥接。未实现 adapter 明确报未完成，不静默输出零结果。E_L2 的后景支架确实能捕获模型后景且不含前景自身。L2 self/gold 分离，文件哈希可追踪。

## Gate 4：保护与泄露

从白名单导出；全新沙箱不能访问作者目录和源历史。源文件及运行时保护正确。干净导入重跑通过，不依赖缓存。公共 contract 的哈希与测试端一致。

## Gate 5：视觉与预算

固定视频/帧采集、VLM rubric、版本/随机性设置、人工抽检和预算。参考帧标定完成；禁止在看到某模型效果后更换拍摄角度只显示其优势。

## 允许输出的结论

未运行：`NOT_RUN`；仅文件生成/静态校验：`SPEC_VALIDATED`；算法/Godot 实际通过才记 `RUNTIME_VALIDATED`。发布使用 `RELEASE_READY`，不能将这三个状态混写。

L3 另有完整源工程运行、真实绑定、合格/错误集成对照等关卡，本轮 L1/L2 发布不代替它们。
