# 通用实现、OJ 与 GPU 证据规范（作者侧）

## 1. 三套产物，不能混用

| 产物 | 作者实现什么 | 被测模型能看到什么 |
|---|---|---|
| CPU float64 参考 | 独立的标量/网格解、解析退化解、随机输入生成器 | 不可见 |
| GPU 合格参考 | Godot 内的真实 Shader/计算核心与效果 | 不可见源码；默认也不提供参考截图 |
| 空白 starter | 中性相机/灯/数据、加载桥、公共 API、无目标逻辑的占位入口 | 可见 |

数值参考与 GPU 参考不能互相调用来产生“独立一致性”。CPU 的解析解/高精度积分用于验证参考实现，正式 OJ 按公开的离散/连续输出定义比较，不能用另一套未声明规则判错。

## 2. GPU 核心与显示必须一致

每题 `query` 读取实际 GPU 算法或状态。纯函数可由相同核心在探针 dispatch 中计算；状态场要读取正在驱动效果的场，不重建第二份 CPU 状态。GDScript 的打包、调度、事件去重和日志不算替代算法。

Godot 的计算 Shader 使用 RenderingDevice 路径；开发时先验证平台与回读能力，见来源 R02。可用 fragment ping-pong 或 compute，不能只因实现路径不同判错。`.gdshaderinc` 与 `.glsl` 不保证可直接互引，Codex 必须验证实际语法，禁止声称一个 include 自动适用于所有后端。

防替身至少包含：核心调用/资源流检查；改变输入后的 probe 与显示同步；实际 GPU 原始输出；作者侧一个“假 probe 正确、画面不使用核心”的错误对照。检查函数名存在、模型自己填写的 JSON 或一张最终截图都不足以证明一致。

## 3. 10 个数值案例的含义

每个算法文档列出 10 个**覆盖组**。Codex 给每组生成固定输入包，可包含多点/多帧；正式每组作为 1 个案例，先检查该组全部必需输出。额外的性质测试不伪装成额外任务数。

公开：输入域、数学/离散约定、输出字段、公开样例、误差规则、性能上限、指标含义。隐藏：正式输入实例、随机种子、标准输出与私有对照程序。正式隐藏输入可以在测试时传给实现，但不得把 expected、测试名称、测试序号和其他答案元数据作为运行时输入。

L2 报告 `new_numeric_pass/10` 与 `inherited_numeric_pass/10`，不将二者混为一个“更高的 L1 分”。交互测试单列。继承版本每轮按同一公开前级契约回归。

## 4. 时间、资源与采集

使用 harness 明确传入的模拟时间和 dt，不用壁钟/TIME 替代测试时间。每步顺序：在 t_n 处理一次事件 → 以公开规则更新到 t_n+dt → 输出该时刻状态。每题的特殊出生/注入时序在公开契约写清。重新 reset 必须清空所有持续状态。

浮点图、法线、密度、高度与速度均是线性数值数据，不施加 sRGB/gamma、色调映射或有损压缩；最终美术图像另采集。原始 GPU 输出可用 float32 二进制加元数据或已验证的无损浮点格式。PNG 只用于展示，不能默认充当数值证据。

GPU 回读需要正确同步；禁止读取上一帧却标成当前帧。诊断回读耗时不计入效果渲染性能，但必须单独记录。无 GPU/无可用回读时记 `INFRA_ERROR`，不得用 CPU 替代后记通过；渲染失败不等于算法得到 0。

## 5. 误差与通过规则

一般标量规则：`abs(y-y_ref) <= atol + rtol*abs(y_ref)`。角度/方向先明确单位和向量范数；布尔、索引、状态事件按精确规则；网格默认检验所有约定采样，不仅均值。

POM 使用空间交点/UV 容差；离散积分比较规定采样的参考，另做收敛诊断；临界角附近采用明确输入间隔，不能用浮点噪声制造未说明的分支题。

Codex 用至少一份合格 GPU 参考、独立 CPU 参考、可行时第二份合法实现，以及文档里的错误对照标定容差。**不得调整阈值直到某个被测模型通过。** 阈值冻结后写入可公开 manifest；未冻结时禁用正式评分。小误差、近阈值记录原值以供人工复核。

## 6. 视觉评价

每题至少包括 A-only（L1）、B-only/诊断（L2）、combined（L2）及受控参数变化序列。评价目标忠实度、局部视觉缺陷与动态连贯性；结构/数值正确性由工具负责，VLM 不推断看不到的代码。

相机轨迹、时间、分辨率、曝光、AA、色调映射、背景及截图批次由作者端固定。默认不允许模型挑选最终评价帧。每个视觉 rubric 使用 0–4 锚定等级并附证据帧；最终展示为 `25*mean(item_scores)`。这只是本版建议的公开评分方式，发布前冻结，不用它抵消硬约束失败。

## 7. 报告状态

`PASS`、`FAIL`、`NOT_RUN`、`INFRA_ERROR`、`BLOCKED_RELEASE` 分离。编译失败记录 `FAIL_COMPILE`；超时记录 `FAIL_BUDGET`；隐藏测试未执行不能记为 0/10 或通过。返回逐组数值、交互项、保护项、视觉项及证据路径，禁止只给总分。
