# C_L3_R｜既有噪声资源复用与原天空保护：公开接入契约 v0.2

## 与前级的关系

保留 C_L1/C_L2 的云影、直接光调制、HG 与雾光程合成。新增工作是从 `public/resource_inputs.json` 指定的既有输入资产获得本题密度数据，并将结果接入真实接收区。本任务的局部云场独立于原天空运动，不要求二者位置对应；原天空必须保持原样。

## 本版新增的密度构造定义

输入 U 与 V 的资源 ID、通道和实际数据布局可从只读工程及元数据读取；数学上 U 为三维标量场，V 为二维标量场。两者按各自原始资源的规定层组织读取，数据处理在场景线性数值空间。task.json 冻结本题读取使用的过滤、寻址、LOD 级别、通道及非负归一化规则，不能自行更改原资源的导入设置。

局部云网格的每个体素中心归一化坐标 u=(ux,uy,uz)，本版定义 `rho_grid(u)=max(0, a*U(u)+b*V(ux,uz)-theta)`，a,b>=0；系数、grid 尺寸与范围由公开配置给出。若原数据需要单位或范围转换，转换必须在发布元数据中说明。随后把该真实 GPU 网格按 C_L1 的三线性密度定义送入原积分核心；不是直接把计算好的透射图作为输入。

允许在 solution 中构造等价的 GPU 派生资源，或保留原资源句柄并使用对应采样方式。每次 reset 必须依据本次配置和实际源资产重建所需状态；不得使用与源无关的噪声或预存最终云影/体积光。正式基线中原天空资源不随模型处理而改变；输入变体只在 reset 前由评测环境按公开域选择。

## 场景作用和保护

只改变指定接收区域的目标方向光贡献，并加入指定雾体；前级环境光不被云透射重复变暗。雾沿相机路径被原不透明深度正确截断，且与主场景使用同一模拟 tick。这里不增加树木对光源路径的体积阴影或多次散射求解要求。

原天空材质、资源导入方式、全局曝光/光源/AA、非目标资源消费者均受保护。可以在 solution 中复制数据或新增转换实现，不能把共享源文件改成满足自身接口的类型。新增显示关闭后，原天空及保护区域应在公开容差内与基线一致。

## 输出与检查

增加 `density_resource_query(uvw)`、真实 `rho_grid` 及其源资源标识/配置 hash；保留 cloud_query 和所有 fog 输出。查询坐标属于普通输入，不含答案；报告必须对应实际驱动云影/体积光的资源。资源 ID 的文字说明不能替代 GPU 采样和下游干预一致性。

算法核心保持 GPU，资源加载/依赖组织可在 CPU。前级20例数值、5组联动及本级数据适配、原消费者保护分别评价。
