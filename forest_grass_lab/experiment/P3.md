# FG01 · S1 / P3

遵守逐子任务实现协议。只修改 grass.gdshader，不修改宿主、场景、相机或资产。工具 update_main/read_main 的名字沿用原协议，实际文件是 grass.gdshader。

先 set_plan 生成 4–8 项计划，每次回复只调用一个工具。每项完成前至少对当前版本调用一次目标场景 step 检查并观察返回的真实 PNG；最后一项还需公开检查，然后 submit。pass 是模型自评，不是独立质量分数。

check(kind=step) 只允许 scene=target（可省略）。params 可包含 camera（overview/roots/top）、wind_strength（0–0.45）、wind_speed（0–3）、wind_direction（XZ 二元数组）、player_position（XYZ 三元数组）。默认相机 overview，默认风强 0.22、风速 1.6、风向 [1,0.35]。设置 player_position 后转为手动玩家，不再自动行走。

每次检查启动全新目标场景，无已有轨迹，768×512，dt=1/60。frames 为 1–3 个严格递增的帧编号，范围 1–720，默认 [1,120,240]。schedule 为 [{frame,set}]，在对应 step 之前设置参数，参数为绝对值。可用它改变风、玩家位置或观察相机，但不能换成自建场景。每个 step 后执行真实渲染；无额外效果预热步骤。

check(kind=public) 不能传入 scene/params/frames/schedule，固定执行题目所有公开案例。4 秒案例截图 [1,120,240]，2 秒案例 [1,60,120]；11 秒案例 [225,420,660]，12 秒反向停留案例 [225,420,720]。反向停留案例按题目给定端点线性插值玩家位置。每个案例独立重开，数据互不继承。

L1/L2 的 public 固定回传 wind_default/240、wind_off/120、strong_crosswind/240 三张 PNG；L3 固定回传 player_without_wind/225、420、660。所有其他公开截图也保存到磁盘。step 回传指定的全部图片（最多三张）。选择规则固定，不按画面好坏选图。

图像在工具结果之后发送，保留在本次会话历史中。没有作者参考代码或参考图输入。只依据收到的证据陈述观察，执行无错误不等于视觉正确；有疑问继续当前子任务。最终提交后另做一次不反馈的公开执行并保存动画。

每项最多 80 次 API 请求、24 次模型发起的检查；HTTP 失败也计入请求次数。可重试的 HTTP/网络错误等待五分钟后重试当前请求，保持已有代码和对话，不重开批次；授权/配置错误停下该模型。预算不会自动追加。
